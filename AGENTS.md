# AGENTS.md — irongall-client

**The verifiable client side of IronGall: the protocol's spec, the Go client and `irongall` command, a client in plain shell on stock `age` and `ssh-keygen`, test vectors, and tests that run the client against a server that forges.** IronGall is end-to-end encrypted, sender-authenticated mail between bots, built so that nobody has to trust its server: everything a box relies on is checked here, in code you can read and by tests you can run.

🛑 **This repo is public: every push publishes.** Never commit a secret, a private key (the vectors' keys are published test keys: § Tests), a token or an internal hostname, and never copy text from a private note without a decision to publish it.

**Judging whether IronGall is secure → `SECURITY.md`:** each promise a box is given, the spec section with the whole rule, the code and test that hold it, and how to report a vulnerability privately. **Changing it → § Contributing, then § Rules by area for the code you touch.**

## Contributing

### Sign off every commit

Each commit carries your human's sign-off, made with `git commit -s` (the Developer Certificate of Origin: `CONTRIBUTING.md`).
- **It is their certification, not yours.** Tell them the repo requires it. With their say-so you may run `git commit -s` for them: it writes the line from their git identity.
- 🛑 **Never sign as yourself, never write a `Signed-off-by:` line by hand, and never put anyone else's name on one.**
- **Name yourself** in an `Assisted-by:` or `Co-Authored-By:` trailer.
- A pull request whose commits lack the line fails the DCO check and is not merged. `CONTRIBUTING.md` has the commands that add it to commits already made.

### Where things are written

- **`PROTOCOL.md` is the spec.** A change to the wire, a check or a refusal changes it in the same commit as the code. It describes the server only as a client meets it (routes, checks, refusals, what it promises to store): never how a server stores things, a setting's value, a person's words, or a document outside this repo. What is specified and not built says so where it is described and in §12, and is an issue in `M1: protocol freeze`.
- **`api/openapi.yaml` is the HTTP layer of `PROTOCOL.md` in OpenAPI 3.1, and no server serves it:** a change to a route, a member, a status, a code or a header changes it in the same commit, and `PROTOCOL.md` governs where they differ. `api/`'s tests hold it to `protocol/`'s codes and members, and `api/apitest` holds a server's answers to it: the fake server here, and every test server in irongall-server. It carries no byte format and no check: those stay in `PROTOCOL.md` and the vectors.
- **`PRECEDENTS.md` is the one place a comparison with another system is kept:** Part 1 sets IronGall beside whole systems, Part 2 each decision beside the system or standard that does the same. A row is added the day a big decision is made. Every claim about another system says how it is known: `read <date>` with its source, `review 2026-10-10`, or `from memory`, never a number from memory as if read. `PROTOCOL.md` cites it and keeps a short mention where one helps, with a pointer; grow no second table anywhere.
- **No judgement is written as a fact,** on any page, in a comment or in an issue: write what was measured, read at a source or decided. Nothing ranks one cipher, key type or design over another without the source that says so, and a comparison's source is in `PRECEDENTS.md`.
- **The README says as little as it can:** what an agent must know to run a box safely, each command once, and pointers. Before adding a line, find one to cut.
  - Two lines are the maintainer's: the status line's freeze date, which moves only on his word, and the line that sends a reader to the open issues.
  - Where the README or the spec states a limit that an open issue plans to change, the issue's number sits beside it: agents judging the service from its pages read a limit with no number as permanent (2026-10-12).
  - The status line never lists the operator or Cloudflare as a limit. Cloudflare is said once, in § No Server Trust, as how irongall.dev runs today, as `PROTOCOL.md` §9 says it.
  - Three tests hold its command lines: `TestHelpAndREADMENameTheEchoBox` here, one in irongall-server for the command its link page gives, and one kept with irongall.dev's site for every command in its `llms.txt`. Change a command line in each place that gives it.
- **`SECURITY.md` is the one place for how to report a vulnerability and for each security claim beside what holds it.** A new claim, or a change to what holds one, edits its row in the same commit; a claim goes there only with the test or code that holds it. Elsewhere, point there: the threat model stays irongall-server's `CRYPTO-ANALYSIS.md`, and what a server sees and can do stays `PROTOCOL.md` §9.
- **Layout:** the repo's is `README.md` § What is here; a box's files are at the top of `client/doc.go`.

### How a design is chosen

- **Priorities, in this order:** the correct encryption; then a server that is feasible and fast, not as cheap as possible; then simple things simple for the user.
- **Before the protocol freeze, a fix is chosen for being correct:** backwards compatibility and leaving the wire unchanged carry no weight, in a design, an issue or a recommendation.
  - 🛑 **Nor does a rule, format or behaviour of our own** (the server's, the spec's, a client's files or the script's): one that forces a workaround is a design question, put to the maintainer with the best design for every side and its cost, and every side changes to the answer together. It hides as a command changing shape, a workaround for the other side's rule, a known variance, or a reason that names what is already written (#126 audits for it).
  - **Nor does an old tool:** the design assumes a current client and a modern library. What the oldest `ssh-keygen` or `age` can do is never a reason for or against a design; the script's floor follows the design.
- **A design follows industry practice, read at its source** (an RFC, a major system's documentation, then its code), never this project's own earlier choice. Where a standard has a reference implementation, its behaviour is the practice: OpenSSH for SSHSIG and certificates, age for age. Where Let's Encrypt meets the same concern as a free public API anyone may call (limits, renewal, revocation, abuse), its practice is the precedent (`PRECEDENTS.md`, Part 2, § 4). A statement of the design that differs is challenged, whoever made it. **A deviation is justified as part of the design,** its reason in `PRECEDENTS.md` beside the systems it differs from; one with no reason there is a defect.
- 🛑 **A format takes a layout others already use, and its overhead is a fixed number of bytes, never a share of the message.** Read what the standards do, and what went wrong with them, before choosing a layout, and give each option's cost beside it. Every format that cannot change after the freeze gets that look once (#39).
- **A speed call is made among standard tools and norms:** never replace a standard function with hand-written code to save CPU, and leave deeper optimisation until real load can be measured.
- **Clocks: every check is exact at the clock of whoever makes it, and whoever makes a time-limited thing leaves `protocol.MaxSkew`, an hour, of room** (`PROTOCOL.md` §0; `PRECEDENTS.md` § Clocks; decided on #40). 🛑 Add no allowance to a check, and never make a thing that asks for exactly what its verifier takes: a certificate starts an hour before it is made, a server takes a prekey up to an hour past what a client asks for, a reader takes a `sent_at` up to an hour ahead. The room covers the maker's own calls too, beside the hour: two minutes for a post in the server's keep of mail (`protocol.PostTime`), an hour for a renewal in the prekey's shortest lifetime (`renewTime`). Exactness to the second is for what is cryptographic, not for how long a server holds mail.
  - 🛑 **A test of anything timed uses two clocks.** Every test here once shared one, so none could see that a box two seconds fast could not register (`client/clock_test.go` is the pattern).
  - A client reports how far its clock is from a server's, as the server's word, and never adopts it or tells its reader to. An outbox entry dated ahead of the clock is held at every attempt. 🛑 A key that mail may be waiting for is never deleted to recover from a wrong clock: a box cannot know a statement was never published.

### Tests

- **Every client passes `testdata/vectors/`,** and the shell client is tested the way agents run shell: a fresh shell per command.
- **`client/` and `cmd/irongall` are tested against `internal/fakeserver`:** an honest in-memory server that a test turns hostile with a middleware (`README.md` § Tests). The forging-operator tests live here, so anyone can run the checks they are told to verify. The fake checks little by design: a test of what the real server enforces belongs in irongall-server.
- **`sh/` is tested by `go test ./sh`:** `sh/test.sh` against an in-shell fake that forges, its verdicts on every vector against the Go client's, and the two clients together. A test skips, naming the tool, when one is missing.
  - 🛑 **`go test` prints `ok` either way, and with age older than 1.3 it tests `--no-pq` boxes only.** Put age ≥ 1.3 first in `PATH` and read `go test ./sh -v` (`mode: KEYTYPE=pq`) before saying the script is tested. `pq()` probes `age-keygen -pq` to stdout: with `-o /dev/null` it was false on every age, and the two-client test ran `--no-pq` only until 2026-10-11.
  - To hold the script to another OpenSSH, build its release (`./configure [--without-openssl] && make ssh ssh-keygen`) and put it first in `PATH`: `go test ./sh -v` names the build and each known variance it met (`PROTOCOL.md` §3).
- **Vectors:** `testdata/vectors/generate.sh` uses stock tools only (age ≥ 1.3 just for the one ciphertext, which it keeps). A re-run must change nothing but what you meant to change: diff the tree. 🛑 **Its keys are PUBLISHED test keys,** RFC 8032's for every Ed25519 key and RFC 6979 §A.2.5's for box C's P-256 identity: never put any other private key in this repo. A certificate is made once and kept, since a second run cannot make the same bytes.
- **No mutation pass:** the hand-listed one was deleted 2026-10-11 as more pain than it found. Do not add one unasked.

### Before and after every push

- **Before:** `gofmt -l .` (empty), `go vet ./...`, `go test -timeout 20m ./...` (`./sh` alone runs about ten minutes, past `go test`'s default), and `golangci-lint run --max-same-issues 0 --max-issues-per-linter 0 --enable gosec,misspell,revive,unconvert,unparam,whitespace ./...`, clean outside `_test.go` (without the two caps it shows at most 3 issues of a kind, so a new one hides behind old ones). There is no CI. `go test` cross-tests against `ssh-keygen`, and skips that where it is missing.
- **After: `needs-audit`.** A change that ships without a second reader (nobody else read it, or what was written after its review has not been read) gets a new issue labelled `needs-audit` in this repo, whichever repo changed; the issue it fixes closes as usual. 🛑 **The issue is the auditor's whole brief:** the commits, the claims to try to break, where to look first, what is known and open, how to run it, and what closes it, so an outside agent with no other context can work from it. Nothing waits on one: it is not a gate. Whoever audits closes it, saying what was read, run and tried, each finding an issue of its own. #45 is the pattern.

## Rules by area

Each rule names the code that keeps it and, where one exists, the test that holds it. 🛑 marks a trap someone has fallen into.

### Every client

- **Verification always on, with no flag to skip it. Fail closed. Message bodies are untrusted data. State lives in `~/.config/irongall/<name>/` (0700), never the working directory.**
- **One on-disk format, in the stock tools' own file formats** (OpenSSH key, age key files), so the shell client and the Go client run the same box. The identity is a plain OpenSSH key file: no seed, no passphrase. A `sent/` record is the line its recipient's `inbox/` keeps plus `receipt`; `aliases` is `<name> <address>` lines, which either client and a person may write, and a name is never moved by a client.
- 🛑 **Prekeys are never derived from a seed, never backed up or synced, never kept where old versions survive (a secrets manager, git, snapshots), and never reused** (`PROTOCOL.md` §1): any of those voids the forward secrecy every box has.
- **Every file a box keeps is on disk before anything depends on it:** written beside it, synced, moved into place, and its directory synced (`writeFile`, `ig_put`, `ig_putline`, `ig_putout`; decided on #99), and a prekey, its statement and its working key are synced before any upload names them. A crash leaves the old file or the new one, never an empty one, which a box would read as a fault.
- **The box's lock is `irongall.sh`'s `lock/` directory,** plus a flocked `lock/pid` so a crashed Go client's lock is taken over; a `lock/` with no `pid` is the script's, never taken over and never written into (`client/lock.go`).
  - **Every command that writes the box holds the lock from start to end, and waits while another holds it** (`hold`, `locked`, `ig_lock`; decided on #62, #83 and #96). A new command that writes the box takes it; one that only reads (`Status`) does not.
  - 🛑 **A writer takes it at its exported entry and nowhere below:** the lock is not re-entrant, so an exported method that holds it calls the unexported twin of another (`syncACL`, `prune`, `resolve`), never the exported one, which would wait for itself. In the script, a command that another command runs works under its caller's lock (`ig_held`).
- **Dependencies are minimums, never pins, moved to the latest by committed updates:** bump `go.mod` in a commit (`go get -u ./... && go mod tidy`, tests green), never inside a build, so every build matches a commit and `go install …@latest` gets the new versions. `go.sum` is checked against the Go checksum database.

### The shell client

- **`sh/irongall.sh` is the proof, not the client to run:** it shows that what the Go client encrypts and signs is what stock `age` and `ssh-keygen` read. It need not gain every feature the Go client gets, and the README says to use the Go client.
- **It is kept explainable:** a check that only buys convenience stays out, and what it lacks is listed in `README.md` § Stock tools instead of Go. 🛑 **A security check is never one of those gaps:** it matches the Go client's verdict on every vector, on OpenSSH linked to OpenSSL.
- **The Go client is the reference, and it follows its library's standard behaviour.** Where a tool the script drives reads a thing otherwise, the script works around it when that is clean, and what is left is a known variance its tests name. The Go client never changes to match the script, and the script need not give a code it cannot. Where OpenSSH's builds disagree (`PROTOCOL.md` §3), the script says what its `ssh-keygen` says, and its tests hold it to that known shape and fail on any other.

### Sending

- **What is encrypted is the envelope's line, its signature, then padding** (`protocol/signed.go`, `seal` in `client/send.go`, `ig_seal`; `PROTOCOL.md` §4.4; decided on #29). It is git's layout for a signed tag, with three rules for a reader taken from what went wrong in git's verifiers (`PRECEDENTS.md`, Part 2, § 3): verify line 1 exactly as decrypted, never anything rebuilt; each part has one place, and nothing after the first END line is read; one signature, one identity, the verifier's exit status.
  - 🛑 **A change to how a reader takes the parts apart breaks one of those rules:** `OpenSigned` and `ig_open` are held to each other on every `plain/` vector (`TestVectorsPlain`), code for code where the script can give the code.
  - 🛑 **A format's overhead is a fixed number of bytes, never a share of the message:** the envelope as base64 inside a JSON object was refused for that.
  - **The outbox's `.P` is the signed line, its line feed included,** in both clients, and it carries the box's identity document. `recv`'s line, `inbox/` and `sent/` are built from the checked fields without it.
- **Every send is padded, at the seal and never before,** with bytes after the signature (`protocol/pad.go`, `ig_padding`; `PROTOCOL.md` §4.3a). The block is counted on the ciphertext, from age's file sizes (`SealedSize`), and each client checks the size of what age wrote and refuses a mismatch. No flag turns padding off or on. Change the arithmetic in both clients together: `TestPaddingIsTheGoClients` holds the script to the Go client, and `TestSealedSizeIsWhatAgeWrites` holds the header sizes to age itself, so an age release that changes them fails there first.
- **A box reads the recipient's box before it posts, and seals to what it then holds** (`readBox`, `resolve`, `post`, `trySend` and `seal` in `client/`, `ig_lookup`, `ig_post`, `ig_seal`; `PROTOCOL.md` §4.1, §4.5, §6.3; decided on #55, #91, #112 and #22).
  - **The read comes before anything is sealed or posted, at every post,** a new message or one that waited: one `GET /v1/<address>`, which carries the prekey and what the server holds of the box's revocations. The Go client asks the revocation servers once for each recipient in a command; the script asks them every time. A read of a box carries no pass, of another box or its own (`lookup` in `client/api.go`, `ig_look`; §4.1, §8; decided on #214): the read is public, and a pass would only have a server count it against the box's own calls.
  - 🛑 **No answer holds the message in the outbox:** a failed read's code is never read as an answer about the message, never passes through `undeliverable`, and never moves an entry to `outbox/failed/` (`lookupError`). "None held" is kept nowhere: nobody signs it, so it has no lifetime, and the one a cache would need is nobody's to invent.
  - **A seal is made for one post and never kept.** The outbox holds the envelope alone, as written; every post, a retry included, dates it last, once the recipient's box is read, and never more than 33 days after it was written (its `sent_at`'s value and no other byte of its line: `protocol.Dated`, through JSON tokens, and `ig_seal`, read back by `sameEnvelope` and in `ig_seal`; decided on #195 and #253, #278, #279), and seals it to the statement `resolve` passes then, signed by the working key in use (`seal` returns what to post and writes nothing; `ig_seal` writes `$IG/seal.P`, `$IG/seal.age` and `$IG/seal.query`, scratch it removes first, and `ig_sent` records `seal.P`). 🛑 **Do not keep a seal to post again:** each check a kept seal needs (a revocation since, a renewal recorded since, a seal cut short: #112, #91, #113) grows with every finding, and all it saves is a lost answer's one send, which the reader's `(from, msg_id)` check already makes harmless. `TestAWaitingMessageInBothClients` holds both clients to an outbox of envelopes alone.
  - **A box signs no mail under a certificate it holds revoked** (`seal`, `ig_seal`; decided on #177): the entry waits in the outbox, and once `recv` or `prekey renew` has the renewal taken, the next flush seals it under the new certificate.
- **Whatever verifies is kept, from a server or from a file** (`Ask`, `KeepRevocation`). A record handed over is refused whole when a part of it does not verify, and its owner is told (`KeepRevocation`, `ig_handed`); a server's answer that does not verify counts as nothing shown.
- **A sender holds what it writes to a reader's rules before anything is kept** (`NewJSONEnvelope`, the read-back in `sendWith`, `ig_send`'s `ig_json` and `ig_envcheck`; decided on #20): a body or subject its reader would refuse is refused whole, never repaired, so a name given twice is never kept once. An envelope that `seal` would refuse is never written to the outbox, where it would wait for good.
- **A prekey serial is signed once** (`client/rekey.go`, `ig_renew`; `PROTOCOL.md` §6.4): a renewal the server did not take is sent again as it was signed, and a new key goes to a later number only when that statement has expired, was made for longer than the box's lifetime now allows (decided on #190), is under a certificate that began less than an hour before the clock (decided on #120), or, in the Go client, another type is asked for. Signing the same key again with a later `not_after` gives a server that fails renewals and keeps the uploads one key without end (found 2026-10-11).

### Reading what others wrote

- **A box never asks the server who a sender is, and pins one only once its signature verified** (`judge`, `pin`, `ig_meet`): the envelope carries the identity document, whose hash is the sender. The one thing it asks about a sender is whether a revocation of it exists, by one read of its box, once in a drain and only after that sender's signature verified. On a send, a peer is pinned only once something its identity signed has verified.
- **A fetch is read to the size its list gives, and no further** (`ciphertext` in `client/api.go`, `ig_one`; `PROTOCOL.md` §5.2): the fetch answers the ciphertext alone, and the list says who sent it and when. A body of another size is an answer that breaks its form, and stops the drain with nothing judged or acked.
- **The replay set keeps each line `protocol.SeenFor` from its `sent_at`, and is pruned by the box's clock only once the server has taken that drain's pass** (`pruneSeen`, `ig_forget`; `PROTOCOL.md` §5 check 9; decided on #196). 🛑 **A prune that drops a line raises `seen-floor` to its cutoff FIRST, and a `sent_at` below the floor, or less than `protocol.TTL` above it, is `stale`** (`seenFloor`, `ig_floor`; decided on #279): pruned before the pass, or with no floor, a clock that steps back makes delivered mail fresh again, and a hostile server replays it (`TestAReplayIsRefusedAfterTheClockStepsBack`); a retry is dated up to a TTL after its first copy, so a floor that held its own `sent_at` let a kept retry through (`TestARetryAboveTheFloorIsDeliveredAgain`).
- **Keys are deleted, and the replay set pruned, by the box's clock only once a server has taken a pass dated by it, and by that pass's date, never by a reading of the clock** (`taken`, `takenBy`, `ownerTaken`, `publish`, `Result.listedAt`, `prune`, `dropRetired`, `pruneSeen`; `ig_taken`, `IG_LISTED`, `ig_prune`, `ig_forget`; decided on #200, #259 and #266): a drain's list answered, or a renewal taken. A clock far ahead is stopped at its pass, one that jumps or steps back while the call is in flight deletes nothing by where it went, and the keys that mail waits for stay (`client/taken_test.go`). 🛑 A new path that deletes by the clock takes a `taken`, which only a pass the server took gives: never `b.now()`, nor a reading taken just before or after the call.
- **A drain is bounded** (`maxDrain*`), and one the server paces (`429 fetch_paced` or `refetch_spent` with `Retry-After` on a fetch) stops as at those limits, with `Result.Paced` and no error: the rest waits on the server.
- **A `304` answers only for the tag its poll sent** (`sameTag` in `drain`; `PROTOCOL.md` §5.1; decided on #149): one about another tag is no answer, nothing is deleted on it, and the kept tag goes (`TestA304AboutAnotherTagIsNoAnswer`). The fake reads `If-None-Match` through `protocol.IfNoneMatch`, as irongall-server does: `*` only as the whole value, each tag through its closing quote. 🛑 A split at commas let one planted tag make every poll `304`.
- **A signature is read as OpenSSH reads it, with two checks more** (`protocol.Dearmor`, `sshsig.Verify`, `ig_blob`, `ig_sshsig`; `PROTOCOL.md` §3; decided on #38 and #86): its armour as `sshsig_dearmor` reads it, `reserved` skipped and signed as empty as `sshsig_wrap_verify` does, the version, NUL and ECDSA-size forms OpenSSH's parsers take (`opensshReading`, in `Dearmor`, so every Go verifier gets it; `sshsig/` stays x/crypto's API and reads exactly); then at most the bound its identity's key type sets (`protocol.SignatureBound`), and an Ed25519 S below L. Where OpenSSH's builds disagree, the rule is the Go client's and the others are the known variances of §3. A check beyond OpenSSH's is a deviation, with its reason in `PRECEDENTS.md`. 🛑 The script reads the armour itself, never through `sed` and `base64 -d` alone, which refused forms `ssh-keygen` takes: `TestVectorsSignatureForm` holds both clients and `ssh-keygen` to one verdict on each `sig/` vector.
- **Every JSON text is read by one set of rules, by every reader** (`protocol.Unmarshal`, `protocol.UnmarshalRequest`, `ig_json`, `ig_shape`, `ig_bytes`; `PROTOCOL.md` §0b; decided on #66 and IronGall-dev/irongall-server#17). A server refuses a member it does not know in what it is sent, and every other reader ignores one (a client in an answer, a box in an envelope), and the rules hold in it.
  - **The parsing is Go's `encoding/json/v2`, so the module needs Go ≥ 1.27.** A check beside it is one it does not make (depth, noncharacters, the integers). 🛑 **Never `encoding/json`'s `Unmarshal` on a text a server, a sender or a file brought:** it matches names in any case and keeps the last of a name given twice. Writing with it is fine.
  - **The script adds to jq what jq does not check:** jq skips a byte-order mark, takes `NaN`, `01` and `+1`, and keeps the last of a name given twice, and glibc's `iconv` takes a code point above U+10FFFF. The script refuses what jq would take otherwise than the text says: a control byte (jq ends a number at a NUL and drops it) and an escaped surrogate outside a pair (jq reads a lone low one as U+FFFD). jq ≥ 1.7.1 is needed: from 1.7 it gives back `1.0` as written, and 1.7.0 can abort on a number a sender writes (CVE-2023-50246). `TestVectorsJSON` and `TestVectorsAnswer` hold its verdict to the Go client's on every `json/` and `answer/` vector.
  - 🛑 **A shell variable drops trailing line feeds and every NUL,** so a value a check depends on is tested in jq or compared as bytes, never through `$(…)`.
  - 🛑 **The script runs in the C locale** (`export LC_ALL=C` at its top), so its patterns and every tool it runs read bytes, as the Go client does: under en_US.UTF-8 `[0-9]` takes a digit that is not ASCII, and under tr_TR.UTF-8 `[A-Z]` misses `I`. `TestTheScriptReadsBytesInEveryLocale` runs the vector tests under both.
  - **A serial is at most 2^53 − 1 everywhere** (`protocol.MaxSerial`), since an answer names one as a JSON number. A JSON member that is a number is exactly `int64` or `uint64`, the two `integers` reads: never `int`, `uint` or `uintptr`, whose width is the build's, nor another width, a float or a type declared on one (`TestWireIntegersHaveAFixedWidth`, which type-checks the package); `int` is for what stays in the process.
- **An identity is a key of a type `PROTOCOL.md` §2 defines** (`identityTypes` in `protocol/identity.go`, `ig_idcheck`; decided on #21): `ssh-ed25519`, which every client makes and verifies, or the optional `ecdsa-sha2-nistp256`.
  - **A type is added in both clients together:** its one exact form, its key checks, and a vector for each document a client must refuse. Where the Go library and `ssh-keygen` differ on a key, the stricter rule goes into the spec and is made explicit in the other client, so one document gets one verdict (`TestVectorBadIdentities`, `TestVectorsIdentity`).
  - **A well-formed document of a type a client lacks is `unsupported_key_type`, never `bad_identity`,** and only once it is known to be the sender's: a malformed document points at tampering, one of another type does not.
  - **So is a prekey of a type a client lacks** (`protocol.ErrPrekeyType`, `RefusedPrekeyType`, `ig_bech32`, `ig_prekeycheck`; `PROTOCOL.md` §0a; `prekey/unsupported-type`): a statement whose key is a well-formed age recipient, a Bech32 string whose human-readable part begins `age` and is neither `age` nor `age1pq`, is refused at a send as `unsupported_prekey_type`, never as one that does not verify, and the key's type is the last thing a statement is held to. 🛑 The script reads the type before it runs `age -r`: age ≥ 1.3 encrypts to more types than the protocol defines, an SSH key among them.
  - **With each prekey a client declares the key types it verifies** (`sender_key_types`, §2c; `IG_SENDERS`): all of them, never `any` unless told to. An optional type is never what a client makes by default, and `init --identity-type` warns.
  - 🛑 **Nothing may rest on a certificate having one set of bytes:** one an ECDSA identity signed has other encodings ((r, n − s), and either number zero-padded up to the 2,049 bytes OpenSSH reads), which anyone can write and both verifiers take (`TestAP256IdentityCertifies`).
  - 🛑 **The script compares a document with itself rebuilt, byte for byte** (`ig_idcheck`): a shell variable drops a NUL, so a test of the variable alone passes a file that holds one (`identity/nul-*.doc`).
  - 🛑 **An identity key's checks live in `protocol.ParseIdentity`, not in `sshsig`** (Ed25519: small order, non-canonical; P-256: the bounds OpenSSH put on a point up to 10.2p1): x/crypto's would not make them, and every identity a verifier uses has passed `ParseIdentity` first.

### Certificates and the working key

- **A box's identity signs certificates and revocations, and nothing else; a working key signs what the box says** (`protocol/certificate.go`, `client/work.go`, `ig_work`, `ig_cert`; `PROTOCOL.md` §2b; decided on #30). Each client makes a new working key and certificate with each new prekey, and keeps it as `work/<serial>` in the names `ssh-keygen` uses. A client asks for 65 days and a verifier takes 66. `CheckCertificate` checks one certificate against an identity and a clock; holding its serial to an order is the caller's (`Resolve` does, for a peer's prekey statements).
  - 🛑 **`ssh-keygen -Y verify` takes a certificate with a critical option, extensions out of the one encoding the Go client's library reads, another key id or serial 0,** so the script reads a certificate's fields from its bytes: `TestVectorsCertificate` holds that, with a `cert/bad-*` vector for each rule. An extension in that encoding, and whatever `reserved` holds, are ignored by both (draft-ietf-sshm-cert-01 §2.1.1).
- **A box proves itself with a pass it signs, and there is no token** (`protocol/pass.go`, `pass` in `client/work.go`, `ig_pass`; `PROTOCOL.md` §6.1b; decided on #36). A client writes it in one form, and `ParsePass` reads it as RFC 9110 §11 lets a recipient (decided on IronGall-dev/irongall-server#18): `FuzzParsePass` holds that every form it takes reads as the values of that one form, and `testdata/vectors/pass/` has each form taken and refused. `Pass.Authorization` writes the one form back, the signature armored again from the blob a verifier reads with nothing in the reserved field, so a server that remembers passes by it checks each once however it is written (`TestAPassWrittenAnotherWayIsOnePass`). The pass is kept in the box and used until 30 seconds before it runs out; if a server refuses it, a client signs another and tries once more. A registration and a prekey upload carry a pass under the certificate of the statement they bring (`publish`), kept only once the server took it. 🛑 **Nothing a server sends is decrypted with a key that reads mail:** the token that was (`IsToken`, found 2026-10-12) is gone.
- **A box's statements are ordered by certificate first:** the certificate's serial, then the prekey's own (`Resolve`, `rekey`, `ig_resolve`, `ig_renew`; decided on #48). A later certificate passes any serial under an earlier one, and a renewal's number is above the served CERTIFICATE's. 🛑 **Comparing prekey serials across certificates brings #48 back:** one use of a taken working key, at the highest serial there is, ended the address.
- **A certificate's serial is its maker's clock in seconds, or one above the highest serial the box knows of when the clock gives nothing higher** (`protocol.SerialAt`, `Init`, `rekey`, `ig_init`, `ig_renew`; decided on #63). The prekey and working key made with it share the number. A box restored from its identity alone is, by the clock, above every certificate made before, so the revocation of everything below it covers them all.
  - 🛑 **A verifier never reads a serial as a time: it compares two.** Add no check of a serial against a clock, anywhere.
  - 🛑 **"One above" stays; do not make it a refusal** (weighed on #73): it covers two renewals in one second, and a lost machine's fast clock, where a refusal would hold back the owner's renewal and revocation (`TestALostMachinesFastClockDoesNotDelayTheRemedy`).
  - 🛑 **A number an attempt took is kept until its statement is published or spent** (`highestBegun`): a new number for every retry would sign a new key each time and leave the waiting one unsent.
  - 🛑 **A test reads a box's number and never assumes one** (`numberOf`, `num` in `sh/test.sh`): every test here once wrote 1, 2 and 3.
- **A send names its prekey by both serials, in its query, and its body is the ciphertext itself** (`protocol.SendQuery`, `postSealed`, `ig_seal`, `ig_post`; `PROTOCOL.md` §4.5): each client writes the serials as the digits it checked, and posts the age file's bytes as they are, never base64 inside JSON.

### Revocation

- **An address is revoked by its identity's own signature, and a client takes "revoked" on nothing less** (`protocol/revocation.go`, `client/revocation.go`, `ig_revcheck`, `ig_gone`, `ig_lookup`; `PROTOCOL.md` §6.3; decided on #14).
  - **A server's `revoked` or `sender_revoked` is checked, never believed:** `proved` reads the box for the record, and only one that verifies makes a `RevokedError`; without one the call has failed and no state changes. 🛑 Neither code may go back into `undeliverable`.
  - **A revocation that verified is kept and never removed** (`peers/<address>/revoke.sig`, `revoked.sig` for the box's own), read and checked again at each use. `Resolve` refuses such a peer before any request, and `judge` refuses its mail, whenever it was signed.
  - **A box that holds its own revocation signs nothing more,** whatever any server answers (`finished`, called in `post`, `receive`, `rekey`, `pass` and `signPass`; `ig_finished`, in `ig_post`, `ig_drain`, `ig_renew` and `ig_pass`; decided on #152). What carries no pass still goes: `status`, `revocation ask`, `revocation keep`, publishing again, `cert publish-revoked`. 🛑 A new call that carries a pass gets it from `pass`, never around it.
  - 🛑 **A working key's signature is not a revocation:** `VerifyRevocation` verifies against the identity's bare key, and the script's signers line carries no `cert-authority` (`revoke/bad-by-a-working-key.sig`).
  - **A negative answer and no answer are different things** (`lookupRevocation`, `ig_lookup`): a box served with no revocation, no such box, or "revoked" with nothing that verifies lets a drain go on, and anything else stops it with the mail still on the server.
  - 🛑 **The statement is fixed text and never gains a field.** What is added later is a second statement under a new tag: a slot nobody fills fails when it is used, and a rule to refuse what a reader does not understand would turn a revoked address back into a live one.
  - **A record names its own type first, `"type":"revocation_record"`** (`Revocations.MarshalJSON`, `checkType`, called by `Unmarshal` and `UnmarshalRequest`, and on the `record` a problem carries; `ig_shape … record`, `ig_revocation`, `ig_revoke`). Every writer writes it, servers in their answers too; a reader takes a record without it and refuses one that names another type (`ErrMemberValue`, `400 bad_request` with `member`). So the line `revocation make` prints is the record, the body every server takes: never print a record with anything beside its own members.
  - **`revocation publish` takes the address in full as its confirmation,** and neither client writes a record unasked: kept beside the identity, it is lost and stolen with it.
- **Certificates are revoked through a serial their identity signs: the highest one verified stands, and nothing lowers it** (`protocol/revokedcerts.go`, `client/revocation.go`, `ig_certscheck`, `ig_certrevoked`, `ig_keepcerts`; `PROTOCOL.md` §6.3a; decided on #51 and #79).
  - **It is verified as a revocation of the address is, under the identity's bare key, then parsed exactly** (`revoked/bad-by-a-working-key`). The script compares the file with itself rebuilt, and compares serials in bash, whose integers are exact.
  - 🛑 **There is no version and no list: do not add a way to revoke fewer.** One that does not verify or runs no higher changes nothing, whenever it arrives, and a certificate once revoked is never taken again. What is kept is checked again at each use, and one that no longer verifies is an error, never "nothing revoked".
  - 🛑 **It is kept as ONE file, the record that carries it** (`revoked-certs.json`), moved into place whole: a statement and its signature in two files can be left one new and one old by a crash, a pair that never verifies again.
  - **A revoked certificate loses everything it signed, whenever it was signed:** `judge` and `ig_judge` refuse its mail as `certificate_revoked`, and `Resolve` and `ig_resolve` refuse a prekey statement under it. The address goes on.
  - **A box never makes a certificate its identity has revoked** (`rekey`, `ig_renew`): the next is numbered above the highest serial it holds revoked, and every renewal first takes what the read of its own box carries and asks each revocation server it lists (`readOwn`, `ig_renew`'s `ig_take` and `ig_revask`; decided on #82). One through 2^53 − 1 leaves none to make, and the box says so.
  - **`cert revoke-earlier` runs `RenewAndRevoke`** (`client/revocation.go`): it reads its box once and asks each revocation server once in the command (`readOwn`, one `lookups`), and goes on past an answer it cannot use (`Remedy.Unread`); it publishes the revocation of every certificate below the number the clock gives (`revokeBelow`), asks again after any `conflict` and signs the higher one; only then does it number the new certificate, one above the revocation, and make it (`makeRenewal`), sending nothing an earlier renewal left (`unused`); and then it sends the renewal. Its words say the box takes no mail only when its own server took the revocation (`Remedy.OwnTook`). Decided on #162, #163, #164, #111 and #130. 🛑 **The revocation goes first, whatever the renewal meets:** once a server holds it, whoever holds the taken working key can spend none of the box's calls there. A box whose own revocation covers the certificate it uses renews at its next drain (`renewIfDue`, `ownRevokes`). The script applies one and makes none.
- **A box asks revocation servers beside its own server, and publishes its revocations to them** (`client/revocationserver.go`, `ig_revservers`, `ig_lookup`, `ig_revoke`; `PROTOCOL.md` §6.3; decided on #52 and #140). Every mailbox server is one, so the tests stand a second fake server in for it. A revocation is of an identity, and an identity belongs to no server.
  - **"Revocation server", always both words:** "the server" alone is the box's own mailbox server.
  - **A revocation server can only add:** what it shows is checked and kept as anything is (`take`, `ig_take`), and its "none held" is its word. 🛑 **No answer from it changes nothing:** it never holds a send or stops a drain. Never let its error reach `post` or `judge`: every one a box listed would be one more way to stop its mail.
  - **It is asked only once the box's own server has answered, with no pass, for ten seconds at most,** and one that gave no answer is not asked again by the same command (`lookups.silent`). The script asks again each time.
  - **Which ones is the owner's to say,** in `Options.RevocationServers`, `$IRONGALL_REVOCATION_SERVERS` or the box's `revocation-servers` file, in one grammar both clients hold a list to. 🛑 None is named by default: the box's own server is one already, and a lookup tells whoever runs another which address its asker corresponds with. A list that cannot be read is an error, and the box asks about nobody until it is put right.
  - **A `410` to a published record, from the box's own server or a revocation server, is taken only once the record that server then serves verifies** (`servesRevocation`, `servesRevocationAt`, `ig_revoke`).
  - **A record is published at every server, whatever the others answer** (`publishRecord`); not everywhere is a failure that says who took it (`NotPublishedError`), and once any server has taken a record its box keeps it. 🛑 What ends an address goes out only with that address written in full: `cert publish-revoked` takes a list and no revocation.

### Who may write to a box

The client holds; the server's ACL refuses (`protocol/acl.go`, `client/senders.go`; `PROTOCOL.md` §5.6, §6.2; decided on #4 and #23).
- **`held/` is not `quarantine/`:** quarantine holds mail that failed a check, held holds mail that passed from a sender the box has not allowed. Keep the two words and directories apart.
- **A policy, `allowed` or `blocked` file that cannot be read stops a drain and a send** (`readSenders`), and is never read as the default.
- 🛑 **An ACL always says whom it lets in:** `Document` writes both lists, an empty one as `[]`, and `CheckACL` refuses one with no `allow`. Never let a writer drop an empty `allow`: under the form first proposed, that read as everyone.
- **Under `server allowed`, the ACL goes before the post** (`SendWith`, `Flush`): a reply the server refuses for it is final. `sender_not_allowed` is in `undeliverable` and in the script's list.
- **Tests:** `env.box` lands every sender's mail, since most tests are of what comes before landing; a test of where mail lands makes its boxes with `heldBox`. `sh/sh_test.go` (`landAll`), the server's tests and its `test/interop.sh` (`gocli`) do the same.

### What a box prints

- **Every command prints JSON lines, one object a line, its `type` first** (`line`, `typed` and `report` in `cmd/irongall/output.go`; `ig_out`, `ig_err`, `ig_wrong`; decided on #17 and #18). What a command did and met goes to stdout, so a reader of stdout alone misses nothing; stderr has only the `error`, `usage_error` and `waiting` lines. A `message` is the client's own words. Help is the one thing printed as text, and nothing switches on whether stdout is a terminal.
  - 🛑 **A line is built by `line` or `typed`, never by formatting text into JSON,** and a mail line is the `inbox/` line's own bytes behind its `type` and `id`: encoding it again would write raw the line breaks it escapes. A new line type goes in the README's table in the same commit, and in both clients where the script has the command.
  - **A line that is also a protocol document is that document, exactly** (§6.3's record): its `type` is part of the protocol's format, never members added around it.
  - 🛑 **In the script, a line printed inside a function whose stdout is captured is lost** (`why=$(ig_judge …)`): such a function writes to `$IG/said`, which its caller prints.
- **Exit status 3 is "done, and the box needs a look"** (`needsALook`): `recv` after a failed renewal, `status` with a non-empty `attention`. Refused mail never changes `recv`'s exit status, because any sender can cause a refusal.
- **Nothing someone else wrote is printed as this client's words** (found 2026-10-11). A refusal is a code from the closed set in `client/errors.go` and `protocol/envelope.go`, with fixed words: never a value, key or field from an envelope, a served identity or a served statement.
  - 🛑 **A server's words are never printed at all** (decided on #43; `PROTOCOL.md` §13): its `detail`, `hint` and `title` are for a person with curl. An API error is its status, a code the client knows under that code's own status and beside its own `type` (`protocol.Problem.CodeAt`, `ig_code`), and the client's own sentence for it (`APIError.words`, `ig_api`), with the members it carries once each is checked to its type, a string member only once it is a value the client knows. A new code gets its sentence in the same commit; `TestAnAPIErrorPrintsNoneOfTheServersWords` puts injected text in every free member of every code; `type` is no free member. 🛑 **Nor is net/http's error printed, which quotes the server** (a status line, a header or trailer line, a `Location`): a call with no answer it could read is named by its method and path, never its query (a list's cursor is the server's), and a kind from a fixed set (`transportError`; `TestATransportErrorPrintsNoneOfTheServersWords`, `TestAListsCursorIsNeverPrinted`).
  - A receipt is checked against the ciphertext posted before it is printed or recorded, and an account name against its form (#5). 🛑 A new error path that formats outside text with `%s`, `%q` or `%v` breaks this rule: `TestARefusalNeverQuotesTheMessage` and `sh/test.sh` § 14 hold the envelope's.
- **A line a box prints or keeps escapes what nobody sees** (`escapeUnseen`, `ig_line`; decided on #19): each line break but LF, and every character of Unicode's `Default_Ignorable_Code_Point`, as JSON escapes them, so nothing hides an instruction from whoever reads it. The list is Unicode 18.0's, kept three times, in each client and in `sh/sh_test.go`, whose `TestWhatABoxKeepsIsOneInBothClients` holds the two clients to it and to each other. A new Unicode version changes all three together. `show` and `peer allow` print a kept line only once it reads back as the line recv kept, and escape it again (`keptLine`): whoever last wrote the file is not known.
- **`quarantine/` keeps a refused message whole, as served, with none of the server's strings in the clear but those of their form** (`keepRefused`, `ig_kept`; decided on #7): an id or address is 64 lowercase hex, a time one `ParseTime` reads, any other string `<name>_b64`. It is read through `irongall quarantine list`, which holds each value to its form again, and `status` names that command, never the files.
  - **Beside it, the Go client keeps what its checks established** (`protocol.Examine`'s `Findings`, `judged`; decided on #44): the clock it judged by, and who signed it only when the signature verifies at its certificate's own start (`signed_by`), otherwise the identity it claims (`claims_identity`), then that certificate's serial and dates and the envelope's `sent_at` and `msg_id`. 🛑 **Never the identity a failed signature carries as its sender, and never anything the sender wrote as text:** a forgery copies an identity to frame it. The script keeps none of it (README § Stock tools).
  - **A refusal for a time is a verdict like any other,** quarantined and acked (`PROTOCOL.md` §5; decided on #44). 🛑 Do not hold such mail on the server to wait for a clock: a client whose clocks are right makes none, and the box's owner judges the rest.
- **A secret is never an argument** (decided on #15): `account adopt` reads the key on stdin, holds it to an adopt key's form before anything is sent, and never prints what it read.

### The command line

`irongall <command>`, or `irongall <group> <command>` where one thing has more than one thing done to it (`cmd/irongall`, on cobra, as gh and docker are; decided on #37). A renamed command keeps no old name: before the freeze there is nobody to keep it for. `sh/irongall.sh` takes the same words for the commands it has.
- **Help in every form a git-like tool gives it** (clig.dev): `irongall help [<command>]`, `--help` after any command, and `<group> help`, to stdout with exit 0. 🛑 **`--help` anywhere after a command prints its help and runs nothing,** whatever else is on the line: `revocation publish` with the address in full and `--help` publishes nothing (`TestHelpRunsNothing`, and `TestTheCommandLine` in `sh/`). `-h` does the same, as in docker: it is in no help, and says on stderr that `--help` is the flag (`MarkShorthandDeprecated`, and the same line from the script).
- **A command line that is wrong runs nothing and exits 2** (`usageError`): a bare group, a command that is not one, a bad flag, the wrong number of arguments, with a `usage_error` line on stderr. A command's `help` is not help when the command takes arguments (an alias may be named `help`).
- **Flags are written with two dashes** in the help, the README, error text and irongall.dev's `llms.txt`, and may come anywhere after the command. 🛑 **No flag has a shorthand, and `-h` is never given a meaning** (`PRECEDENTS.md` § 4 has why): `TestFlagsAreWrittenWithTwoDashes` holds every command to both.

### Names and modules

- **The name** is written IronGall in the README's prose, and `irongall` in every command, label, path and format.
- **Module path:** `github.com/IronGall-dev/irongall-client`. Installing must never depend on the irongall.dev server.
- **`sshsig/` implements exactly the API the Go team accepted for `x/crypto/ssh`** (proposal golang/go#68197): `Sign(s Signer, rand io.Reader, message []byte, namespace string) ([]byte, error)` and `Verify(pub PublicKey, message, signature []byte, namespace string) error`. `Verify` accepts sha256 and sha512, and reads `reserved` as OpenSSH does (`TestReservedAsSSHKeygen`). When `x/crypto` ships it, check that its `Verify` does the same, then switch the import and delete ours. Its implementation, CL 659715, is unmerged at x/crypto v0.58.0 (2026-10-09).
