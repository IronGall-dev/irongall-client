**Purpose:** the verifiable client side of irongall.dev. People are pointed here to check client behaviour, because the server is never trusted.

**`PROTOCOL.md` is the spec, and it is public like the rest** (it moved here from the server's repo on 2026-10-12). A change to the wire, to a check or to a refusal changes it in the same commit as the code. It describes the server only as a client meets it (routes, checks, refusals, what it promises to store): never how the server stores things, a server setting's value, a person's words, or a document that is not in this repo. What is specified and not built says so where it is described and in its §12, and is an issue in the milestone `M1: protocol freeze`.

**`PRECEDENTS.md` is the one place a comparison with another system is kept** (public here since 2026-10-12): Part 1 sets irongall beside whole systems, Part 2 each decision beside the system or standard that does the same. A row is added the day a big decision is made. Every claim about another system says how it is known: `read <date>` with its source, `review 2026-10-10`, or `from memory`; never a number from memory as if it were read. `PROTOCOL.md` cites it at its top and keeps a short mention where one helps at that step, with a pointer; do not grow a second table anywhere. Like the spec it holds nothing of how the server is built, nobody's words, and no file outside this repo.

**Design priorities, in this order** *(Drew, 2026-10-12)*: the correct encryption; then a server that is feasible and fast, not as cheap as possible; then simple things simple for the user. **Until the protocol freeze, a fix is chosen for being correct:** backwards compatibility and leaving the wire unchanged carry no weight, in a design, in an issue or in a recommendation. **Nor does an old tool:** the design assumes a current client, a modern library and a correct clock, and what the oldest `ssh-keygen` or `age` the script runs on can do is never a reason for or against a design. The script's floor follows the design.

**Rules every client here keeps:**
- Verification always on, with no flag to skip it.
- Fail closed: a failed check stops, never warns and continues.
- Message bodies are untrusted data.
- State lives in `~/.config/irongall/<name>/` (0700), never the working directory.

**Layout:** the repo's, `README.md` § What is here; a box's files, the top of `client/doc.go`. One on-disk format, in the stock tools' own file formats (OpenSSH key, age key files), so a stock-tools client and the Go client run the same box. The identity is a plain OpenSSH key file, no seed, no passphrase.
- **`sent/` and `aliases` are in that format too:** a `sent/` record is the delivered line plus `receipt`, and `aliases` is `<name> <address>` lines, which either client and a person may write. A name is never moved by a client.
- **The consumer lock is `irongall.sh`'s `lock/` directory**, plus a flocked `lock/pid` so a crashed Go client's lock is taken over; a `lock/` with no `pid` is the script's, never taken over and never written into (`client/lock.go`).
- **`sh/irongall.sh` is the proof, not the client to run** *(Drew, 2026-10-12: "use of standard encryption tools proves that nothing janky is going on in go")*: it shows that what the Go client encrypts and signs is what stock `age` and `ssh-keygen` read. So it need not gain every feature the Go client gets, and the README says to use the Go client.
- **It is kept explainable:** a check that only buys convenience stays out, and what it lacks against the Go client is listed in `README.md` § Stock tools instead of Go *(Drew, 2026-10-11: "aim for an explainable [irongall.sh]" · "we're allowed to list flaws like non lock safety on it vs the go client")*. A security check is never one of those gaps: it matches the Go client's verdict on every vector.
- **Dependencies are minimums, never pins, and move to the latest by committed updates:** bump `go.mod` in a commit (`go get -u ./... && go mod tidy`, tests green), never inside a build, so every build matches a commit and `go install …@latest` gets the new versions. `go.sum` is checked against the Go checksum database.

**Tests:** every client passes `testdata/vectors/`, and a stock-tools script is tested the way agents run shell: a fresh shell per command.

**A prekey serial is signed once** (`client/rekey.go`, `ig_renew`): a renewal the server did not take is sent again as it was signed, and a new key goes to the next serial only when that statement has expired or, in the Go client, another type is asked for (the script keeps the pending key whatever type is asked). Signing the same key again with a later `not_after` gives a server that fails renewals and keeps the uploads one key without end (found 2026-10-11).

**What is encrypted is the envelope's line, its signature, then padding** (`protocol/signed.go`, `seal` in `client/send.go`, `ig_seal`; `PROTOCOL.md` §4.4; decided on #29, 2026-10-13: *"i like having this be the git signed tag method. it is ALWAYS better when we can piggy back on something vetted"*). It is git's layout for a signed tag, and three rules for a reader came from what went wrong in git's verifiers (`PRECEDENTS.md`, Part 2, § 3): verify line 1 exactly as decrypted and never anything rebuilt; each part has one place and nothing after the first END line is read; one signature, one identity, the verifier's exit status. 🛑 A change to how a reader takes the parts apart breaks one of them: `OpenSigned` and `ig_open` are held to each other, code for code, on every `plain/` vector (`TestVectorsPlain`). 🛑 **A format's overhead is a fixed number of bytes, never a share of the message** *(Drew, 2026-10-13: "a few more bytes is wrapper. 1/3 more is a broken waste of bytes all around")*: the envelope as base64 inside a JSON object was refused for that.
- **The outbox's `.P` is the signed line, its line feed included,** in both clients, and it carries the box's identity document. `recv`'s line, `inbox/` and `sent/` are built from the checked fields without it.
- **Every send is padded, at the seal and never before,** with bytes after the signature (`protocol/pad.go`, `ig_padding`). The padding is outside what is signed, so a message already on a block gets none: that settles what the `pad` member's flat 9 bytes were for *(Drew, 2026-10-12, then on the new layout: "we've also fixed padding")*. The block is counted on the ciphertext, from age's file sizes (`SealedSize`: a header fixed per key type, a nonce, a tag per 64 KiB chunk), and each client then checks the size of what age wrote and refuses a mismatch. No flag turns padding off or on. Change the arithmetic in both clients together: `TestPaddingIsTheGoClients` in `sh/` holds the script to the Go client's, and `TestSealedSizeIsWhatAgeWrites` holds the header sizes to age itself, so an age release that changes them fails there first.

**Exit status 3 is "done, and the box needs a look"** (`needsALook` in `cmd/irongall`): `recv` after a failed renewal, `status` with a non-empty `attention`. Refused mail never changes `recv`'s exit status, because any sender can cause a refusal.

**Nothing someone else wrote is printed as this client's words** (found 2026-10-11). A refusal is a code from the closed set in `client/errors.go` and `protocol/envelope.go`, with fixed words: never a value, key or field from an envelope, a served identity or a served statement. A server's `detail` and `hint` go through `plain` and are printed in quotes after "the server says". A new error path that formats outside text with `%s`, `%q` or `%v` breaks this: `TestARefusalNeverQuotesTheMessage` and `sh/test.sh` § 14 hold the envelope's.

**A box's identity signs certificates and nothing else; a working key signs what the box says** (`protocol/certificate.go`, `client/work.go`, `ig_work`, `ig_cert`; `PROTOCOL.md` §2b; decided on #30). Each client makes a new working key, with a new certificate, each time it makes a new prekey, and keeps it as `work/<serial>` in the names `ssh-keygen` uses. A client asks for 65 days and a verifier takes 66. `CheckCertificate` checks one certificate against an identity and a clock; holding its serial to an order is the caller's (`Resolve` does, for a peer's prekey statements). 🛑 `ssh-keygen -Y verify` takes a certificate with extensions, another key id or serial 0, so the script reads a certificate's fields from its bytes: `TestVectorsCertificate` holds that control, and a `cert/bad-*` vector for each rule.

**A box proves itself with a pass it signs, and there is no token** (`protocol/pass.go`, `pass` in `client/work.go`, `ig_pass`; `PROTOCOL.md` §6.1b; decided on #36). The pass is kept in the box and used until 30 seconds before it runs out; if a server refuses it, a client signs another and tries once more. A registration and a prekey upload carry a pass under the certificate of the statement they bring (`publish`), which is kept only once the server took it. Nothing a server sends is decrypted with a key that reads mail: the token that was (`IsToken`, found 2026-10-12) is gone.

**A box asks the server nothing about a sender, and pins one only once its signature verified** (`judge`, `pin`, `ig_meet`): the envelope carries the identity document, whose hash is the sender. On a send, a peer is pinned only once its prekey statement verified. A drain is bounded (`maxDrain*`).

**Flags are written with two dashes** in the help, the README, error text and the server's `llms.txt`. Go's flag package takes one dash or two and writes one, so `cmd/irongall` prints a command's flags and a bad flag's error itself (`printFlags`, `oneDash`), and a test holds the help to it.

**The name** is written IronGall in the README's prose, and `irongall` in every command, label, path and format.

**Module path:** `github.com/IronGall-dev/irongall-client`. Installing must never depend on the irongall.dev server.

**`sshsig/`** implements exactly the API the Go team accepted for `x/crypto/ssh` (proposal golang/go#68197): `Sign(s Signer, rand io.Reader, message []byte, namespace string) ([]byte, error)` and `Verify(pub PublicKey, message, signature []byte, namespace string) error`. Verify accepts sha256 and sha512. When `x/crypto` ships it, switch the import and delete ours. Its implementation, CL 659715, is unmerged at x/crypto v0.58.0 (2026-10-09).
- 🛑 **Ed25519 key checks (small-order, non-canonical) live in `protocol.ParseIdentity`, not in `sshsig`**: x/crypto's would not make them, and every identity a verifier uses has passed `ParseIdentity` first.
